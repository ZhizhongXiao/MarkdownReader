# 路线图

当前版本：1.0.0-rc1，33 项实机验收已通过（见 [验收清单](QA-CHECKLIST.md)）。

本页只写现在与下一步；为什么选择某个方案留在 Git 历史与 [更新日志](CHANGELOG.md)。

## 现在

- 稳定 1.0.0-rc1：以修复和微调为主，继续维护稳定、可复现的完整打包流程。
- 升为 1.0.0 待许可证与正式发布决定。
- 主题系统 v2 已在 `refactor/vscode-office-integration` 分支实现，**尚未进入 1.0.0-rc1，也不在已发布产物中**：
  每份生成的 HTML 都内嵌 Modern / Office / VS Code，阅读时即时切换；主题与明暗模式是两个独立状态，
  切换只改 CSS 状态，不重新渲染正文。

## 下一步

### 1. Office 与 VS Code 的兼容清单与增强

- 整理「兼容范围 → 主题表现」的对照清单，明确两套主题各自支持到什么程度。
- 按清单补齐增强：Office 面向打印分页与表格，VS Code 面向长代码与紧凑目录。
- 结论并入 [兼容范围](MARKDOWN.md) 与对应主题的 README。

### 2. 外置主题与 GUI Theme Builder（主题系统 v2 的剩余部分）

- 外置主题规范：主题只描述视觉（参数与资源），外壳与交互保持唯一实现；安装位置在 Phase 7 定型。
- GUI Theme Builder：用标准参数生成主题（字体、颜色、尺寸、布局与装饰资源），产出契合该规范的外置主题。
- 目标：新增主题不必复制阅读器交互与布局，也不必改动 MarkdownReader 源码。

## 质量目标

生成的 HTML：离线可用、单文件自包含、目录可导航、长文可阅读、打印可接受、不依赖 CDN 与服务器。

桌面程序：普通用户无需安装 Python；正式包无需用户安装 Node；GUI 可稳定完成单文件与批量转换。
