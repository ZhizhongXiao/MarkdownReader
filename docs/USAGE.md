# 使用说明

本页说明桌面程序的操作、输出规则与常见问题。
安装与构建见 [开发与构建](DEVELOPMENT.md)，Markdown 与 HTML 的兼容范围见 [兼容范围](MARKDOWN.md)。

## 启动

- 正式发布：双击 `MarkdownReader.exe`；便携 ZIP 解压后运行其中的 EXE。
- 源码运行：`python main.py`。
- 需要 Windows 10 / 11（64 位）与 Microsoft Edge WebView2 Runtime；正式包已内置 Python、Node.js 与渲染依赖。

## 一次转换

1. 添加输入：点「添加文件」（支持 Ctrl / Shift 多选）、点「选择目录」，或从资源管理器拖入文件与文件夹。
2. 选择输出目录。
3. 需要本次文档携带外置主题时，在左侧「外置主题」里勾选（安装与卸载在设置页；不勾选就只带内置主题）。
4. 点「开始转换」。
5. 在「列表」页签查看逐文件状态；完成后点「打开 HTML」，或点「输出目录」。

右侧工作区有三个页签：「列表」是本次转换清单，「主题预览」显示内置或已安装主题的外观示意。顶部会显示当前预览主题；左右三角按钮按 Modern、Office、VS Code，再按外置主题安装列表的顺序逐个切换，并在两端循环。也可以点击左侧外置主题行直接预览。预览只影响这个页面，不写配置，也不影响生成的 HTML，更不是所选文档的实时渲染。「日志」正常时静默、出现警告或错误时显示数量。「自动打开」负责打开阅读入口，批量生成索引时优先打开索引。

阅读时的主题由生成的 HTML 自己记住：打开 HTML 后可在页面上切换 Modern / Office / VS Code
（以及文档携带的外置主题），刷新后仍停在上次选择。

## 输出规则

单文件转换：

```text
notes/demo.md  →  输出目录/demo.html
```

多文件（复选或拖入）全部先进入清单并可查看逐文件状态：重复输入自动去重，输出文件冲突在写入前拦下。

文件夹批量转换，未开启「保留目录结构」：

```text
输出目录/
  文档A.html
  文档B.html
  索引-源文件夹名.html
```

开启「保留目录结构」后，整套产物落在「输出目录/源文件夹名-HTML/」下：

```text
输出目录/
  源文件夹名-HTML/
    第一章/文档A.html
    第二章/文档B.html
    索引-源文件夹名.html
```

索引页列出全部文档、按文件夹分组、可搜索、可折叠，并可复制所在文件夹的绝对路径。

## 生成的 HTML

每个 Markdown 输出一个独立 HTML，本地图片内嵌、清单内链接改写、阅读器功能都在文件内：
写法与处理规则见 [兼容范围](MARKDOWN.md)。

## 设置与日志

用户数据（设置、外置主题、日志与 WebView2 数据）按运行方式放在三处之一，内部结构完全一致：

```text
源码运行   <仓库>/.runtime/
便携目录   <应用目录>/data/
单文件 EXE %LOCALAPPDATA%\MarkdownReader/

{用户数据根}/
  profile/config.json              设置（首次保存或首次成功转换时写入，单纯启动不创建）
  assets/themes/external/          已安装的外置主题
  runtime/MarkdownReader.log       启动日志
  runtime/WebView2/                WebView2 数据
```

- **源码运行**：用户数据属于工作树下的 `.runtime/`。
- **便携目录（onedir）**：用户数据位于应用目录的 `data/`；删除整个应用目录即可连同用户数据一起移除。
- **单文件 EXE（onefile）**：用户数据与 EXE 分离，固定放在 `%LOCALAPPDATA%\MarkdownReader`；移动或重命名 EXE
  不会丢失设置与外置主题。

其余事实：

- 仓库只提供 `config.example.json`，不提供 `config.json`。
- 输入记录只保存第一个输入来源的目录，不保存完整的多选文件清单。

### 移除用户数据（单文件 EXE）

设置页提供「移除 MarkdownReader 用户数据并退出」：

```text
删除  设置（profile/）、已安装的外置主题（assets/）、运行数据（runtime/，含日志与 WebView2）
保留  MarkdownReader.exe 本身
确认  按钮在 5 秒倒计时结束后才可用；执行后程序退出
```

便携目录版本没有这个入口，也不需要：删除整个应用目录即可（用户数据在它的 `data/` 下）。

## 打印

打印由浏览器的打印引擎决定。纸面统一为白纸，主题的浅蓝底与左右两条框线画在正文列上、长度随正文；
关闭打印对话框里的「背景图形」只会丢掉蓝底，框线保留。分页、字体替换与纸张缩放仍受浏览器和打印机驱动影响：
Office 主题针对 Edge 打印做过优化，但不追求与 Word 逐页一致。

## 常见问题

### 浏览器没有自动打开

先确认「自动打开」已启用；未启用时 HTML 仍已写入输出目录。
自动打开把结果以 `file://` 地址交给系统默认浏览器：若系统里 `.html` 的默认应用不是浏览器
（例如仍指向已停用的 IE）就不会打开；也可以把生成的 HTML 直接拖进浏览器窗口。

### 生成的 HTML 里图片不显示

本地可读的图片已经内嵌，不依赖原图文件；网络图片和原始 HTML 中的资源需要保证可访问。
源图片不可读时页面保留原引用，并在日志里给出可读路径的提示。

### 提示找不到 Node.js，或公式没有渲染

正式包只使用内置 Node：出现该提示说明打包物不完整，请重新获取发布包。
源码运行时确认已安装 Node.js（`node -v` 可用），并在 `node_renderer` 中执行过 `npm install`。

### GUI 打不开或显示空白

确认已安装 Microsoft Edge WebView2 Runtime；Windows 10 / 11 通常已内置，或可通过 Edge 组件更新获得。
